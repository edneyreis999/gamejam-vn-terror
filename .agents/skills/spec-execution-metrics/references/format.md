# Published format and independent reading

Format version **1**, collector **1.0.6**. Artifacts are UTF-8 JSON files at `execution-metrics/<execution>/<producer>/<record-id>.json`, relative to the consuming spec. Each record contains `version`, `collector`, `id`, `execution`, `producer`, `kind`, `clock`, `data`, `refs`, and nullable `supersedes`. The ID hashes execution, producer and stable publication key; it is independent of location. `clock` contains UTC, monotonic seconds and a boot-session UUID fingerprint, independent of hostname and calendar adjustments. Compare monotonic values only within a domain. Missing/invalid boot identity deliberately produces incomparable domains. Earlier collector domains remain unchanged; upgrading cannot make their intervals comparable retroactively.

Publication flushes a temporary file and atomically hard-links it into its final name without replacement, then syncs the directory. Only `*/*.json` files are accepted. Dot-prefixed pending files are never observations. Replaying the same key and measurement body reuses its record and original collector version, including after a collector update; a different body is a conflict. Producers own separate directories and never replace published files. Keep superseded files in the Git delivery. File names and directory enumeration are not chronological ordering.

## Data fields

The helper rejects unrecognized kinds/fields. Nullable fields represent unknown values, never observed zeros. Text supplied by an operator must contain only public measurement labels; automated redaction is a second defense, not permission to pass private content. `task`, `spec`, and `evidence` paths are relative to the spec. `refs` and `supersedes` contain record identities, so they survive relocation. Evidence outside the spec can use `../`; it remains optional when only the spec travels. Do not use absolute private-log paths as portable dependencies.

| Kind | Data |
| --- | --- |
| `execution` | `spec`, `candidate` (including relevant dirty-input fingerprint), `environment`, coordinator `session` |
| `segment` | `session`, `reason`; records explicit re-entry, never fabricates an uninterrupted span |
| `participant` | `session`, metadata-confirmed `parent`, `inclusion` (`own`, `inclusive`, `unknown`), nullable `baseline`, `entry_turn`, `source_version` |
| `activity_start` | `session`, nullable `task` for spec scope, `category`, `state` (`active`, `wait`, `pause`), optional `parent` activity and `verification_type`, `environment`, `tool` |
| `activity_end` | `activity` ID; the envelope clock is its end |
| `command_start` | `session`, `task`, `activity`, redacted `argv`, `candidate`, `checks`, `attempt`, `verification_type`, `environment`, `tool`, `acceptance` marker |
| `command_end` | `command` ID, `returncode` (negative means signal), external `duration_seconds`, nullable `runner_seconds`, `evidence` |
| `acceptance` | `task`, `candidate`; envelope time precedes acceptance checks; no task-state mutation |
| `finding` | `finding` stable identity, `task`, `candidate`, original `channel`, `classification`, `origin`, `discovered_at`, original `acceptance`, `evidence`, `rationale` |
| `finding_link` | `finding`, `relation`, nullable `activity`, `evidence`; append confirmations, corrections and retests |
| `freeze` | `session`, `participant` record, frozen `turn`, latest `position`, `mode` (`turn` or `position`), optional `inflight` flag recorded at freeze |
| `token` | `session`, `participant`, `source`, nullable `previous`, component `delta`, `issues`, `inclusion` |
| `quality` | `code`, `detail`, `affected` record/interval, `evidence` |
| `reconciliation` | `session`, `participant`, `freeze`, nullable `last_source` fingerprint, `state`, `issues`, optional observed `end_position`/`end_utc`; append distinct provisional/final results |

A token source/baseline holds only `session`, zero-based JSONL line `position`, `fingerprint`, `timestamp`, `turn`, and cumulative `usage`. Fingerprints cover those measurement fields excluding the fingerprint itself. Available components are `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens`. No transcript, message, prompt, last response, environment value, account quota or process output is copied. A malformed source line creates a source-quality gap.

## Reader algorithm

Use `metrics --spec SPEC --run RUN query`. This operation reads published JSON only and needs neither Codex nor the original machine. Copy the entire spec or at least its metrics tree under another spec directory and repeat the same query to verify portability. The command's JSON is a derived view, not a mandatory additional report or a second task ledger.

1. Validate versions and producer/file identities. Report unreadable or unsupported records as gaps; quarantine a connected correction family when an unreadable envelope identifies its record/target. `published_file_count` inventories every JSON file, while `record_count` counts readable supported records. Keep the original inventory for retention checks.
2. Follow `supersedes` from root to leaf. A single valid correction chain contributes its leaf once; references to its earlier revisions resolve to that effective record. Conflicting branches, missing targets, changed kinds or altered original finding provenance are interpretation gaps, not permission to pick the newest file. Preserve all history. Metadata corrections retain the original event clock for execution/activity/command timing, acceptance and freeze boundaries; the correction envelope retains its own publication clock. Derived activity and command rows identify their original `measurement_record`. Corrections cannot reconstruct a missing measurement clock. Append-only finding links are not replacement findings.
3. Deduplicate token events by verified session and position, checking measurement fingerprint, previous boundary and delta. Exclude conflicting observations from combined arithmetic and report them. Subtract cumulative components separately; absent baseline/component, negative reset or incompatible subset/total semantics yields unknown, not zero. A repeated cumulative value can validly contribute zero. Cached input is within input and reasoning output within output; do not add either subset to the total. Uncached input is input minus cached input only when both are known.
4. Report each session separately. Add only established `own` streams to the observed own-session subtotal. Do not add `inclusive` aggregates again. Unknown inclusion prevents an exact hierarchy claim. Inspect participant gaps and collection state as well as the subtotal; a known partial amount is not complete usage.
5. Resolve activity starts/ends by ID. Missing/conflicting ends or clock-domain changes keep duration unknown. Exclude parent containers; union overlapping intervals per agent/domain for accumulated agent duration, then union across agents/domain for occupied duration. Their difference is concurrent overlap. Wait/pause duration is separate. UTC entry-to-freeze elapsed time includes pauses and differs from late final-response token boundaries. External command duration is monotonic; runner-reported duration stays separate.
6. Attribute tokens conservatively from cumulative snapshot intervals. One activity containing the entire interval yields `interval` precision, not proof of a model-call boundary. Multiple overlapping activities yield one `mixed` amount with all activity IDs. Partial/missing links remain `unattributed`. Never split tokens by time. Task/category views link mixed records without adding them to each group's attributed totals. Duration group sums may overlap and must not be added as exclusive effort.
7. Unsupported finding labels remain visible outside counts with an explicit gap. New publications reject unsupported channels, classifications and origins. An evidenced correction may repair an unsupported legacy label; the first valid discovery channel in a correction chain remains immutable, as do discovery time, identity, task/candidate and original marker. Count unique confirmed product findings only with evidence/rationale. `e2e` findings count as delivery defects only after the matching task/candidate acceptance marker. Persona product discoveries have their own count; original discovery survives later tests and repairs. Group introduced, pre-existing and unknown origins separately. Unclassified, infrastructure, test and obsolete-expectation findings remain visible outside product counts.
8. Read the latest reconciliation per participant together with quality records. A position boundary frozen during an unfinished turn retains its excluded-tail gap even after that turn finishes. A closed counter window does not erase earlier missing preparation, activity ends, unknown inclusion or source failures. Later reconciliation occurs outside the frozen window; an immutable provisional record remains evidence of the earlier pending state.

The view exposes activity rows; task/category/session breakdowns; verification type/environment/tool dimensions; command and runner durations; token attribution partitions; linked investigation/fix/retest effort; separate finding counts; and collection gaps. `observed: null` means no supported component observation. A numeric `observed` value is only a subtotal, accompanied by interval and unknown counts. Valid zero discoveries describes the observed scope, not absence of all defects.

Before an authorized commit, inventory all published JSON, verify ignore rules and the proposed commit contents, including correction history and final reconciliation. After an authorized merge, verify contents and independent reading from the destination branch. Pending Git operations stay pending; this module never commits or merges.
