# ADR-004 — Limit native-editor QA to an editability check

- Date: 2026-09-11
- Status: accepted user scope refinement
- Scope: V-008 and task 07; inherited by QA planning and final verification

## Decision

The user requested that opening RPG Maker serve only to confirm that VNPictureBusts is editable through the editor. They do not want extensive testing inside RPG Maker.

Use one short session in a disposable project to locate a representative native plugin command, open its argument dialog and confirm that a position or scale field can be changed and accepted. One representative command is sufficient. Do not require repeated per-hero/per-scene checks, save/reopen/export cycles, a playtest launched by the editor or a 2x2 demonstration inside the editor.

The complete native-data inventory, runtime effect of an authored change, all-eight tavern coverage, 2x2 fixture, visual layouts, saves and controls remain verified through static checks, native integration and the game in Chrome. These are separate evidence from the editor editability check, not reasons to expand the editor session.

## Consequences

Task 07 retains V-008 ownership with this narrower editor sensor. QA reuses its evidence rather than opening the editor again for each scenario. Retest the specific editor check only if a defect or relevant command-metadata change invalidates it. No new approval gate is introduced, and an unavailable editor check must not be claimed as passed.

This supersedes the earlier end-to-end editor/save/revision/game demonstration wording while preserving native authoring as the product requirement and ADR-003's uninterrupted execution policy. No implementation or playtest is performed by recording this decision.
