# ADR-003 — Preload all tavern images through CoreEngine

## Current status — 2026-09-14

**Partially superseded by [ADR-G002](../../../../docs/adrs/adr-g002-remocao-de-atalhos-editoriais.md).** The editorial map shortcut previously used to open the preload list (Map003/event014) is removed. CE351 remains directly editable in the native database and reachable through actual native execution paths. Its file list, functional callers before presentation, entry/return/Continue coverage and asynchronous provider behavior remain required.

This does not retire or weaken tavern preload. The implementation-pending statement below records the original approval date; task08 and verification.md contain the later delivery evidence.

## Historical decision

Status: accepted by explicit user request on 2026-09-12. Documentation amendment; implementation remains pending.

## Decision

Add the installed CoreEngine's System: Load Images command for all images used by the tavern. This is a scoped exception to ADR-002's preload exclusion. Preloading the rest of the game remains outside this spec.

Keep one editor-authored file list in a native Common Event named Taverna — Carregar imagens, reachable from the tavern map. Invoke it through native calls before tavern presentation on entry/return. Cover Continue paths that resume into tavern interactions, without depending only on a New Game initialization event or changing saved campaign decisions. Reuse the same helper/list at the required native entry points.

Cover the backdrop, all eight stage portraits, all conversation busts including Ivaí, interface/button/panel graphics, destination previews, roster presentation and map-piece overlay shown in the tavern. Include every variant regardless of the current party, deaths or route eligibility. The programming contract records the current 29-file baseline; implementation must reconcile it with the final migrated tavern's actual image references.

Use VisuMZ_0_CoreEngine / SystemLoadImages and its native file-list selectors. Do not add a Bridge/Presentation loader, Script readiness barrier, guessed wait, asset manifest or revision tool. The provider command starts asynchronous requests; it does not guarantee all files are ready before the next command or add immediate Retry for late errors. Default MZ/provider loading and recovery remain in force.

## Evidence and verification

Source inspection identified 28 distinct picture files in the tavern's stage, dialogue, destination and map-overlay Common Events, plus Dryland_Tag currently drawn by Bridge. All 29 files exist in img/pictures. This is source coverage, not a preload execution result.

RQ-009, V-008 and S06 cover the command, complete file selection, ordering before use, first entry, return and Continue. Observe cold/delayed loading without converting the provider's asynchronous behavior into a custom blocking requirement. No game file, asset or plugin setting was changed by this amendment.
