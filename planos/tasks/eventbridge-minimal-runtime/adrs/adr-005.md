## Context and motivation

The user found Map003/event003 Gorvak misleading: it calls CE005, while the playable portrait choice calls CE005 directly from CE003. Directed mouse/keyboard observation confirmed that the interaction runs under map event001, bypassing event003. A read-only survey found 42 such authoring-entry candidates across 29 map files. Two static callers do not establish two useful player entry points.

CE005 also embeds a repeated screen cleanup before conversations. Pictures belong to Game_Screen and survive native map transfers, so new maps do not eliminate explicit visual cleanup. A single shared conversation map would require routing back to the selected hero. The user proposed one actual interaction map per hero instead, then authorized only Gorvak as a representative experiment before deciding on the other seven.

This increment is appended to the existing spec at the user's explicit request. Earlier evidence remains the historical baseline. The earlier instruction to defer the 42-shortcut follow-up is superseded by the user's request to include and implement it on this branch.

## Decision for the experiment

1. Create Map037, **Conversa — Gorvak**, as a child of Taverna in MapInfos. Its automatic map event owns the actual menu, native dialogue/bust commands, successful-selection response, full-party response, and return. The map contains the authored interaction; it is not a wrapper calling CE005.
2. The tavern's Gorvak portrait choice transfers to Map037 using native commands and ends its current CE003 path. Map037 offers **Conversar**, **Selecionar** / **Retirar do grupo**, and **Voltar à taverna**. Conversation and selection return to the hero menu; explicit return or cancel goes back to Map003. The other seven heroes retain their current interaction model.
3. CampaignRules remains the only owner of formation legality. Native events query H1/current formation and call CaptureContext/Action for the existing TOGGLE_HERO action. Entering, talking and returning are observational; the map does not become a new campaign phase. Dead H1 cannot be interacted with; automatic formation disables manual changes; full-party rejection preserves membership.
4. Transfer boundaries explicitly retire the outgoing pictures. Preserve the tavern backdrop and reuse the existing H1/Ivaí art and dialogue without new assets or prose. Gorvak is visible in the hero menu; Ivaí enters for his conversational participation and leaves before selection/menu. Native commands in the new map define a readable experimental framing; shared styles used by other heroes are unchanged.
5. Extend ObservationBegin with an optional numeric `unit` argument (0/default uses the current Common Event). This lets map-authored units retain H1's existing reading identities 82–85. Complete marks only the active unit; transfer/cancel resets provider modes. No text-address registry or campaign-rule change is introduced. Retire the now-unreferenced CE005 and CE082–085 as null slots, preserving every other Common Event ID.
6. Remove the 42 confirmed map-entry shortcuts as null slots, preserving automatic events and all IDs. The original inventory is retained in task16. The shortcut operation does not delete their Common Event destinations; retiring the five H1 Common Events belongs only to experiment1. CE004 configuration and CE351 preload remain required and accessible in the native database.

## Alternatives considered

- Keep the current design and label the map entries as editing shortcuts: small change, but retains independent selectors and the misleading ownership that motivated the request.
- Share a cleanup Common Event while keeping all conversations in CE005–012: addresses duplication, but does not test map-owned hero authorship.
- Use one generic conversation map: fewer maps, but requires selecting/routing the hero inside another controller.
- Migrate all eight heroes now: rejected for this branch; broader adoption requires a new analysis after this representative implementation and human acceptance.

## Lifecycle and persistence

Native transfer does not end the source interpreter. Both boundaries must finish the actual source path before the destination autorun takes ownership. The destination cannot accidentally continue the tavern's choice loop. Return rebuilds the tavern from current campaign facts, retaining destination, membership, deaths and consumed absence effects.

No new save point is added. SaveCore AfterTransfer stays false; existing campaign checkpoints remain authoritative. Directed Continue checks use only earned native saves. Changed map/event lists can make old saves structurally incompatible; no migration guarantee or revision gate is added. The explicit unit IDs retain read history whenever native state is otherwise loadable.

## Consequences and limits

The author can edit the real H1 flow under Taverna → Conversa — Gorvak. This costs two map transfers per visit and adds a deliberate return action after selection. It also requires explicit picture ownership and focused verification of input, audio, Options/HIDE, FAST, return and Continue. A new map is not a claim of automatically isolated pictures, faster execution or superior usability.

This experimentally amends RQ-002/003/006/009 map-entry assumptions, ADR-002's H1 routing and ADR-003's map shortcut, while preserving direct native calls elsewhere. The other three human topics, provisional art/text acceptance, engine/vendor contracts and unrelated campaign behavior remain unchanged. No new dependencies, remote services or build are permitted.
