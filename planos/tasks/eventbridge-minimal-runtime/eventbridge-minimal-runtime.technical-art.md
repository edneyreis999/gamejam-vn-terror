# Technical art and composition contract

This contract owns the image, bust and memorial portions of RQ-006–RQ-009 in the [spec](spec.md). Lucas owns the art direction and final framing. New prepared assets may be produced as part of implementation after spec approval; none were generated by this interview.

Events own VNPictureBusts entry/focus/exit commands, native pictures, moves, tones and opacity. Preserve the current authored transforms, including legitimate user edits such as Gorvak's current scale; do not restore obsolete 100% defaults from old tests. The current provisional scene art retains its status.

Remove the automatic Bridge erase/rebuild cycle. An author explicitly exits the busts when the conversation ends. Returning from Options or a supported native save must preserve the intended visible participants; any required checkpoint composition is an explicit event and does not replay narrative or decisions. No renderer in the new presentation adapter may reconstruct prefixes or infer who should be on screen from dialogue ownership.

Prepare eight memorial portrait derivatives in img/pictures with the required face framing, from the current source images. Preserve the source files and record the source-to-derivative mapping. Also inspect the panel/auxiliary images that currently use _drylandCrop: provide ready-to-show assets or native composition for every active crop consumer. Do not remove hero cropping while silently retaining a cropped panel dependency.

The memorial event selects the prepared portrait and uses native picture scale, position and opacity for the transition to the grave. No runtime crop rectangles, expanded bust crop, ghost sprite or custom crossfade renderer remain. Demonstrate compositions for 0, 1, 3 and 8 deaths; preserve the one-screen memorial and accurate death/route/encounter captions. Preparing a correctly framed asset is part of this change; declaring unrelated source art final is not.

Dead heroes disappear on their first tavern return through native event animation. Several deaths fade simultaneously for one second; surviving heroes stay in place and preparation stays usable. If the player leaves early, the next return shows the empty positions. Reduced motion immediately uses the empty positions. Dead portraits never become selectable during a fade.

Loading uses the default MZ/installed-provider behavior, as accepted after native investigation in [ADR-002](adrs/adr-002.md), with CoreEngine System: Load Images now required for every tavern image by [ADR-003](adrs/adr-003.md). Keep the full file selection in Taverna — Carregar imagens, reachable from the tavern map. Include background, eight stage portraits, hero/Ivaí conversation busts, UI/panels/buttons, destination previews, roster and the map overlay shown there. The programming contract lists the current 29-file baseline; update the native command's selectors when the migrated tavern introduces or replaces assets. This is an editor field, not a separate manifest/revision step.

CoreEngine's command starts loading and does not wait for bitmap readiness. No project image-wait command or loading hook replaces Bridge's removed interception. Ordinary loading delays and native error timing remain accepted; use Retry where supplied. Required assets must exist, arbitrary frame waits must not mask loading, and preloading outside the tavern remains excluded. Verify the tavern with a cold cache, on return and after Continue; selecting a file in the command is not proof of timely visible presentation.

Acceptance requires viewing the edited event in MZ and observing the actual render, normal/reduced motion and Options/Continue. Existing screenshots can inform art direction but cannot prove the new lifecycle. The [verification contract](verification.md) owns evidence and human acceptance status.
