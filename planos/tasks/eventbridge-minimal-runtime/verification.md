## Reusable native checkpoints for decision testing

User direction, 2026-09-12: actively reuse save/load to test alternative player decisions without replaying the whole campaign for every variant. This is the default setup for repeated directed scenarios when a compatible checkpoint exists. It does not add a player-facing manual-save/rewind feature: locked/current SaveCore still overwrites the campaign's current file. Multiple campaign slots alone do not preserve earlier decisions. QA therefore preserves immutable copies of genuine native checkpoints outside the game and loads a working copy for each branch.

1. Reach the checkpoint once through recorded player inputs and await the actual autosave and matching persisted index. Choose the nearest existing checkpoint **before** the decision being tested, allowing a short native reread after Continue. Inspect the persisted state, not merely the later state visible in memory; a terminal save cannot test the opposite final choice.
2. Capture the unchanged native payload, selected file ID, global save index and required native storage/UI reading state. Use the existing `rpg-maker/qa/native-save-archive.mjs` / `directed-adapter.mjs` machinery after its task-14 migration away from file0/revision gates. Keep master archives under `docs/qa/evidence/eventbridge-minimal-runtime/checkpoints/<id>/`; list them in the current QA guide/report rather than a second durable registry.
3. For every alternative, prepare a fresh isolated context from an unchanged copy **before its first page opens**, using the original local origin/game/file identity. Open Continue, select that actual file and play the tested choice through the native UI. Do not rewrite campaign fields, remap slots, set a seed, restore storage while the game runs or disable autosave. New autosaves affect only the working context; the master and other branches remain unchanged.
4. Bind each archive to its producer run/input transcript, source hashes, origin/game ID, file/index/payload hashes, saved phase/map/interpreter boundary, party/deaths/routes/read status and the choices reachable from it. Each child run records its parent archive/hash, omitted prefix, actual chosen alternative, expected result, observed result and resulting checkpoint. A copied save supplies setup; it does not prove the new branch's result or a fresh traversal of its prefix.
5. Reuse valid checkpoints across keyboard/mouse, motion, visual, audio and reading-mode variants when their saved facts fit the scenario. Record changed presentation preferences and obtain fresh affected observations. Preserve ordinary same-profile A/B isolation and actual close/reopen tests; two clones of one campaign do not replace two independently created campaign files. Keep one representative fresh New Game-to-ending journey; execute both route orders and all required outcomes using additional branches where valid.

| Native checkpoint family | Reused decisions/observations | Boundary to preserve |
| --- | --- | --- |
| Tavern before departure/route choice | Hero selection/removal, destination alternatives, mouse/keyboard and roster | A persisted formation boundary; play any unsaved preparation after Continue |
| Revealed encounter before approach | Available approach alternatives, reread and retreat/cancel | Same revealed assignment, party and prior reading facts; play the actual approach/retreat |
