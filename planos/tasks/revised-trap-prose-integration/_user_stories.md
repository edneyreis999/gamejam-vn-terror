# Player stories — Revised trap prose

- As a player, I want each trap's description and choices to describe the same situation, so I can relate my selected action to its consequence. RQ-001/002.
- As a player, I want the game to explain why my approach failed before asking whom to sacrifice, then show that hero's farewell and the resulting death in order. RQ-003/004.
- As a player, I want longer descriptions and consequences to remain readable at my pace, with the same controls and without accidental choices. RQ-005.
- As a returning player, I want Continue to preserve what was already decided, even if it restarts unsaved reading. RQ-006.
- As a narrative author, I want the accepted text and any exceptions to be traceable, so further revisions do not silently replace the agreed version or its approval status. RQ-007.

These product outcomes are accepted under D-001/D-002, with the reviewed source treated as prototype wording (D-003). Technical design is approved under D-004 in [the spec](spec.md); integrated gameplay remains unverified.

D-005/D-006 revise verification and save preparation, not these player outcomes; see [ADR-003](adrs/adr-003-proportionate-prose-verification.md). Controls and Continue remain preserved baseline behavior without dedicated regression gates in this increment.
