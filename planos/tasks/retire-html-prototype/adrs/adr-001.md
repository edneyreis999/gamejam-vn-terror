# ADR-001: Use only the RPG Maker MZ implementation

## Status

Accepted on 2026-09-10. After reviewing the historical-reference, save and asset constraints, the user explicitly approved the complete spec set ("Aprovo"). Implementation was not started at approval time; it was subsequently completed and accepted on 2026-09-10, as recorded in [verification.md](../verification.md).

## Context at approval

The MZ increment has been accepted, but the repository still contains a retired executable directory and documentation that tells agents to use it as reference material. Earlier MZ ADR-002 explicitly retained that offline reference. Active memories also continue to describe the earlier runtime as a default.

## Decision

The user's current request supersedes that retention policy: remove the root `retired HTML artifact` directory and remove documentation references to it. Ongoing implementation, examples and implementation evidence must use `rpg-maker/The Dryland Drowned/`. The canonical GDD remains the authority for design; supporting tools/tests and documents retain their existing separate locations.

The user also explicitly requests all documentation references removed. Historical prose is therefore sanitized narrowly, preserving dates, outcomes and creative statuses instead of redirecting past claims to the current game. Completed-spec behavior is not rewritten. No retained copy of the former game becomes a fallback or test oracle.

## Consequences

Asset constraint explicitly confirmed during the review interview on 2026-09-10: all existing assets inside the MZ project remain untouched at their current paths and filenames, with identical bytes. No unused-asset cleanup, relocation, renaming or regeneration is authorized. Deleting the retired directory only removes its own copies. This constraint is included in the final approved spec set.

Interview clarification accepted on 2026-09-10: the user permits historical mentions of the earlier implementation, strictly provided they cannot direct agents to seek references or any other material in the retired directory. This confirms the distinction between preserving historical facts and retaining navigational or evidentiary guidance. The complete spec set was subsequently approved in the same interview.

Save compatibility clarification accepted in the same interview: project development may proceed without migration of incompatible old saves. Apply ADR-037: refuse incompatible native layouts without deleting the old save, keep Novo jogo available, and preserve Continuar for compatible saves. This acceptance resolves the cleanup's stated compatibility consequence; it does not mandate rejection of every existing save. The full spec set was subsequently approved in the same interview.

- Consumers must be resolved before deletion, including the native-inventory test and documentation asset tools.
- Existing MZ assets, licenses, approved behavior and attribution must survive independently.
- Positive project instructions must agree across GDD, root guidance, memories and readmes.
- Native source-comment edits can change file hashes. The existing ADR-037 save refusal policy applies; the approved spec records the accepted consequence and adds no migration policy.
- Merely banning model access while retaining the directory does not satisfy the requested deletion.
