# Source map — Coreto English localization

This map records where each key comes from. The game does not read it at
runtime; `Languages.tsv` is the only prose owner (ADR-002). Every key in the
table has exactly one row here, and every player-facing native source maps to
a key or to an explicit exception.

## Key convention

- `<area>.<scene>.<speaker|passage>.<n>`: narrative Show Text blocks, for
  example `prologue.tavern.gorvak.1`. `<n>` counts blocks inside one scene
  and speaker. It never encodes a command index.
- `choice.<scene>.<approach|option>`: choice captions. Every representation of
  the same choice (102, 402 and the approach picture label) shares one key.
- `ui.*`: menus, Options, Save/Load and window labels.
- `sys.*`: System terms, database display names and plugin vocabulary.
- Other areas (for example `title.*`, `dest.*`, `memorial.*`, `credits.*`)
  follow the same dotted, lowercase, semantic style. Use `_` inside a segment.
- Keys describe meaning and context. Two strings that match in Portuguese but
  mean different things get different keys.

## Markup model (D-018)

- Show Text: one key per block (the 101 header plus its 401 lines). Face, bust
  and speaker metadata stay in the 101 header. The PT cell joins the 401 lines
  with one space and keeps any explicit `<br>`.
- Control tags and block wrappers stay in the event around the key:
  `$[key]<Bind Picture: 50><Hide Choice Window>`, `\FS[22]<WordWrap>$[key]`,
  `<center>\FS[32]$[credits.title]`.
- Multi-line picture text uses `<WordWrap>` in the wrapper. Structural breaks
  in the wrapper are `<br>`, never `\n` in a cell.
- Control Variables (Script) literals shown through `\V[n]` hold the unresolved
  key as their value (D-023a/c). The row lists the variable and every assigner.

## Columns

| Column | Content |
| --- | --- |
| Key | Table key |
| Native owner/field | Map/event/page/command index, Common Event, database field or plugin parameter path; for variables, `V[n]` plus its assigners |
| PT source | Current approved Portuguese copy, verbatim (401 lines joined by a space) |
| Source hash | First 12 hex digits of the SHA-256 of the PT source |
| Context | Scene, speaker or function, and what the player sees around it |
| Treatment | `—`, `<I>`, `\EFFECT<Preset>`, `<CAPS>`/`<CHAOS>`, or `<br>` notes (D-021) |
| Editorial state | `draft`, `reviewed` or `accepted` |

Editorial states: `draft` (translated by the implementing agent), `reviewed`
(checked against the separate agent's findings and addressed), `accepted`
(Edney's explicit editorial decision, V-005).
